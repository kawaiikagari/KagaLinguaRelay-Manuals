日本語版 — 導入編

はじめに

KagaLinguaRelay は、Second Life内およびSecond Life Marketplaceで販売される翻訳リレーです。公開チャットを参加者の言語に合わせて翻訳します。はじめに、ご利用になる翻訳サービスのAPIキーを取得し、engine_config を設定してください。

1. APIキーを取得する

DeepL

  1. DeepL公式 Quickstart を開き、DeepL API のプランを選んで登録します。
  2. DeepL APIアカウントの API Keys からキーを取得します。
  3. DEEPL_KEY=取得したキー の形式で設定します。Free APIキーは通常 :fx で終わります。

DeepL公式: Access and authentication

Azure Translator

  1. Microsoft公式: Create and configure Azure resources for Translator を開き、Azure Translator リソースを作成します。
  2. リソースの Keys and Endpoint からキーを取得し、作成時に選んだリージョン名を確認します。
  3. AZURE_KEY=取得したキー|リージョン の形式で設定します。例：AZURE_KEY=your-key|japaneast

複数キーを使う場合も、各キーに対応するリージョンを | の後へ記載します。

AzureのKey 1／Key 2と複数キー

同じAzure Translatorリソースに表示されるKey 1とKey 2は、別々の利用枠を持つ2個のキーではありません。同一リソースのキーを安全に交換するための交代用認証キーです。両方をengine_configに書いても、トークン、無料枠、課金枠、翻訳容量は二倍になりません。

両方を書くメリット：KagaLinguaRelayは2本を別々のActive Keysとして交互に使います。片方のキーだけが無効になった場合は、そのキーをOFFにしてもう片方で後続の翻訳を続けられます。翻訳機全体を止めずにキーを交換できることが重要な利点です。なお、同じリソース全体の429制限、利用枠、サービス障害にはもう片方のキーも同じく影響されます。

停止なしの交換手順：Key 1とKey 2を登録した状態で、交換する側（例：Key 2）をAzure portalで再生成します。古いKey 2は無効になりますが、翻訳機はKey 1で継続します。engine_configのKey 2を新しい値に書き換えてリセットすれば、二本とも再び使える状態になります。

実際の翻訳容量を増やす場合：別のAzure Translatorリソースを作成し、そのリソースから一方のキーを追加します。別リソースのキーならリクエストが順番に分散され、片方だけが429待機や401／403／456でOFFになっても、もう片方で翻訳を継続できます。

Microsoft公式: Rotate API keys

APIキーの取り扱い

APIキーは翻訳サービスの利用者アカウントに紐づく重要な情報です。engine_configを編集する際は、APIキーが公開された場所に残らないよう注意してください。

2. engine_config を設定する

  1. engine_config ノートカードを開きます。
  2. 使用するキーの行から先頭の # を削除し、自分のAPIキーへ置き換えます。
  3. Azureは AZURE_KEY=your-key|region の形式で、キーごとに対応するリージョンを書きます。

重要：APIキーの設定

翻訳を利用するには、選択した翻訳サービスの有効なAPIキーを engine_config に正しく設定する必要があります。APIキーが未記入、無効、誤入力、利用停止、または利用上限に達している場合、翻訳は実行されません。選択中エンジンに使えるキーがない場合は、オーナーチャットにエラーが表示され、翻訳機のホバーテキストが赤い ERROR 表示になり、オーナーへ日英併記の翻訳停止警告IMが送信されます。

3. スクリプトを入れる場所

親プリム 0 ├─ Manager ├─ Que1 ～ Que4 ├─ RateGate └─ DispatchBroker 子プリム 1 ～ 8（各プリム） ├─ Worker └─ Sender

親プリムには上記6種・合計8本のスクリプト、各子プリムには Worker と Sender を1本ずつ入れます。engine_config と必要に応じた ALLOW_LIST は親プリムへ入れます。

3. 起動確認

  1. オブジェクトをリセットします。
  2. オーナーチャットに、選択中エンジンと Active keys が表示されることを確認します。
  3. 翻訳機から20m以内で公開チャットを行い、翻訳を確認します。

赤い ERROR 表示になった場合は、選択中エンジンに有効なキーがありません。engine_config と API Menu のキー状態を確認してからリセットしてください。

English Edition — Getting Started

Before You Start

KagaLinguaRelay is a translation relay sold in-world in Second Life and through Second Life Marketplace. It translates public chat according to each participant's language. First, obtain an API key for the translation service you will use and configure engine_config.

1. Obtain API Keys

DeepL

  1. Open the official DeepL Quickstart, choose a DeepL API plan, and sign up.
  2. Get a key from the API Keys area of your DeepL API account.
  3. Add it as DEEPL_KEY=your-key. Free API keys normally end in :fx.

DeepL: Access and authentication

Azure Translator

  1. Open Microsoft's Translator resource guide and create an Azure Translator resource.
  2. On the resource's Keys and Endpoint page, copy a key and note the region selected when creating the resource.
  3. Add it as AZURE_KEY=your-key|region; for example, AZURE_KEY=your-key|japaneast.

With multiple keys, write the matching region after every key, following |.

Azure Key 1, Key 2, and Multiple Keys

Key 1 and Key 2 shown for the same Azure Translator resource are not two keys with separate quotas. They are alternate authentication keys for safely replacing a key on the same resource. Listing both in engine_config does not double tokens, free quota, paid quota, or translation capacity.

Why list both: KagaLinguaRelay alternates the two as separate Active Keys. If only one key becomes invalid, the relay disables that key and subsequent translations can continue with the other. The important benefit is being able to exchange a key without stopping the whole relay. The other key cannot bypass a 429 limit, quota, or service outage affecting the same resource.

Replacement without stopping: with Key 1 and Key 2 registered, regenerate the key you want to replace in the Azure portal—for example Key 2. The old Key 2 becomes invalid, but the relay continues with Key 1. Replace Key 2 in engine_config with its new value and reset the relay; both keys are then available again.

To increase actual translation capacity: create a separate Azure Translator resource and add one key from it. Keys from separate resources are used in turn, and translation can continue with the other resource if one enters 429 waiting or is disabled after 401, 403, or 456.

Microsoft: Rotate API keys

API Key Handling

API keys are important credentials associated with your translation-service account. When editing engine_config, take care not to leave keys in publicly accessible places.

2. Configure engine_config

  1. Open the engine_config notecard.
  2. Remove the leading # from lines you will use and replace the example values with your own keys.
  3. For Azure, use AZURE_KEY=your-key|region and write the matching region after each key.

Important: API Key Configuration

To use translation, you must correctly enter a valid API key for the selected translation service in engine_config. If the API key is missing, invalid, entered incorrectly, disabled, or has reached its usage limit, translation will not run. If no usable key remains for the selected engine, an error is shown in owner chat, the relay shows red ERROR hover text, and the owner receives a bilingual Translation Stopped warning IM.

3. Script Placement

Root prim 0 ├─ Manager ├─ Que1 through Que4 ├─ RateGate └─ DispatchBroker Child prims 1 through 8 (each prim) ├─ Worker └─ Sender

Place the eight scripts listed for the root prim into the root. Put one Worker and one Sender into every child prim. Put engine_config, and optionally ALLOW_LIST, into the root prim.

3. Verify Startup

  1. Reset the object.
  2. In owner chat, confirm the selected engine and Active keys count.
  3. Use public chat within 20 metres of the relay and confirm translation.

If a red ERROR display appears, the selected engine has no usable key. Check engine_config and the API Menu key state, then reset.
